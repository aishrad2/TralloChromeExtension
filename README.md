# Trallo Chrome Extension

Trallo is a Manifest V3 Chrome extension for organizing trip plans in a side
panel. Each trip is stored as a Google spreadsheet in the user's Drive, which
can also be opened and edited directly in Google Sheets.

## Implemented

- Google sign-in through `chrome.identity`.
- Create, list, edit, and delete trips. A trip spreadsheet is initialized with
  tabs for Flights, Hotels & Housing, Bucket List, Packing List, Budgeting &
  Expenses, and Notes & Brainstorming.
- Add, edit, and delete planning items in the trip modules, including manual
  flight and hotel entry.
- Share a trip spreadsheet with another person as a viewer or editor.
- Cache trip data in `chrome.storage.local` and save form drafts in
  `chrome.storage.session`.
- Detect changes made directly in Sheets by checking Drive's modified time,
  polling while the panel is visible, and refreshing when it regains focus.
  The panel also provides manual refresh and offline/error feedback.
- Use stable row IDs and validate sheet headers so sorting rows does not break
  edits and removed/renamed required columns can be reported.
- Derive trip status, countdown, next-step guidance, expense totals, and packing
  progress for the trip overview.

The extension currently uses manual entry for flights and hotels. Automatic
capture from Google Flights or Expedia, content scripts, and map/day-scheduling
features are not implemented. See [design/v1featuresspec.md](design/v1featuresspec.md)
for the broader product specification and [design/wireframes/](design/wireframes/)
for UI references.

## Develop

```sh
cd Trallo-Chrome-Extension
npm install
npm run dev
```

## Build

```sh
cd Trallo-Chrome-Extension
npm run build
```

The development command runs Vite in build-watch mode and writes the unpacked
extension to `build/`; it does not start a web server. In Chrome, open
`chrome://extensions`, enable **Developer mode**, and choose **Load unpacked**
with the `Trallo-Chrome-Extension/build` directory. Reload the extension after
the watched build updates it. Chrome associates unpacked extensions with their
absolute path, so load it again if you move the project.

## Google sign-in and API setup

The OAuth consent screen's **Test users** list lets those accounts authorize an
unverified app; it does not remove Google's unverified-app warning. After
authorization, Trallo also needs both **Google Drive API** and **Google Sheets
API** enabled in the same Google Cloud project as the OAuth client. If Trallo
shows an access warning, check that the loaded extension uses that OAuth
client ID and that its Chrome extension ID is registered on the client.

## Commands

Run these from `Trallo-Chrome-Extension/`:

| Command | Purpose |
| --- | --- |
| `npm run dev` | Build and rebuild on source changes |
| `npm run build` | Type-check and create a production extension bundle |
| `npm run lint` | Run ESLint |
| `npm test` | Run the Vitest suite once |
| `npm run test:watch` | Run Vitest in watch mode |

Load the generated `build/` directory in Chrome using **Load unpacked** to
exercise the production build.

## Tests

The Vitest suite covers date and summary calculations, spreadsheet row mapping
and header validation, repository row operations, trip creation and
synchronization, and sharing validation. Tests run in Node with Chrome APIs
stubbed where needed; they do not replace manual end-to-end testing in Chrome
with a configured Google account.

## Development notes

- Keep Google API access in the service/repository layer rather than in UI
  components.
- Update the typed tab schema and row mappers together when changing spreadsheet
  columns. Row changes should continue to use stable IDs, not row positions.
- Keep `build/` generated by Vite; make source changes under `src/` and static
  asset changes under `public/`.
- Keep design references outside the Vite project so they are not included in
  the extension bundle.
